**Domain** ([src/Domain/](web/app/plugins/currency-converter/src/Domain/)) — no WordPress function anywhere in it, per invariant 10:

- [Currency.php](web/app/plugins/currency-converter/src/Domain/Currency.php) — code + display metadata; `normalize_code()` is the single place a code's shape is decided, so `'usd'` and `'USD'` can't become two rows. JPY's `decimal_digits` of 0 survives instead of defaulting to 2.

The constructor *refuses* a float; [`from_float()`](web/app/plugins/currency-converter/src/Domain/Rate.php#L153) is the one sanctioned boundary (`json_decode` gives floats and PHP has no flag to stop it), so `grep from_float` lists every place precision could be lost. Excess decimals round half-up with string arithmetic, not `round()` — and not `bcmath` either, so the domain depends on no extension. Zero, negative, exponent notation and anything too wide for `DECIMAL(24,12)` are rejected rather than silently clamped by MySQL.
- [RateRepositoryInterface.php](web/app/plugins/currency-converter/src/Domain/RateRepositoryInterface.php) / [CurrencyRepositoryInterface.php](web/app/plugins/currency-converter/src/Domain/CurrencyRepositoryInterface.php) — ports declared in the domain, implemented in `Db\`.

**Exceptions** ([src/Exception/](web/app/plugins/currency-converter/src/Exception/)) — three types plus a marker interface. They extend different SPL bases on purpose: `UnknownCurrencyException` and `InvalidAmountException` are `InvalidArgumentException` (the call is wrong), `RatesUnavailableException` is `RuntimeException` (the call is fine, the data isn't there yet). Its message says so outright: *"TRY is a known currency, but no USD to TRY rate is stored. Run `wp currency rates update --force`."*

**Repositories** ([src/Db/](web/app/plugins/currency-converter/src/Db/)) — one multi-row `INSERT … ON DUPLICATE KEY UPDATE` per batch, rate bound `%s`, no `(float)` cast on any read, `orderby`/`order` reduced to allowlisted literals before they reach `ORDER BY`. `map()` is memoised per request. Identity rows are built first and the payload's own base→base row is *dropped*, not merged.

`Schema::rates_table()` / `currencies_table()` now take an optional `$wpdb` so a repository names its tables from the handle it was given.

**Freshness** is checked against `fetched_at` in the table, not against an option — the data decides, so an option that drifted from its rows can't cause a sync against rates it thinks are missing. 23 hours, not 24, so a daily job's jitter never pushes it to the next day. **The lock** is a 60-second transient released in a `finally`, and `--force` overrides the window but never the lock. It's a check-then-write, not a compare-and-swap; two requests in the same millisecond can both take it, which costs exactly one extra request because the loser then finds fresh rates. That's documented in the class rather than dressed up as a mutex.
