# Конвертер валют — модуль для WordPress

Модуль для WordPress: хранит предопределённый список валют, раз в сутки загружает курсы с
[freecurrencyapi.com](https://freecurrencyapi.com/), сохраняет их в базе данных и предоставляет
сервис конвертации и страницу в админке со всеми сохранёнными курсами.

Модуль реализован как плагин в `web/app/plugins/currency-converter/`. Вокруг него — проект
WordPress в стиле Bedrock, запускаемый в Docker: ядро, плагины и темы устанавливает Composer,
конфигурация лежит в `config/`, корень документов — `web/`.

*English version: [README.md](README.md).*

## Что нужно

**Docker с Compose v2, и больше ничего.** PHP, Composer, WP-CLI и MariaDB работают в контейнерах —
устанавливать их на машину не требуется. Нужен `git`, чтобы клонировать репозиторий, а `make` —
удобство: если его нет, вместо `make bootstrap` выполните `./bin/bootstrap.sh`.

## Запуск — три команды

```bash
git clone <repository-url> test-project
cd test-project
make bootstrap
```

Это вся установка. Копировать `.env` заранее не нужно: `bin/bootstrap.sh` создаёт его из
`.env.example` и при первом запуске генерирует в него восемь уникальных ключей и солей.

`make bootstrap` устанавливает зависимости, поднимает контейнеры, устанавливает WordPress,
активирует тему **и модуль валют**, публикует демонстрационную страницу (см. ниже), проверяет
конфигурацию и печатает адрес и учётные данные. Команда идемпотентна — повторный запуск ничего не
меняет и ничего не переустанавливает.

| | |
|---|---|
| Сайт | http://localhost:8080 |
| **Конвертер — начните отсюда** | **http://localhost:8080/currency-rates/** |
| Админка | http://localhost:8080/wp/wp-admin |
| Курсы (админка) | http://localhost:8080/wp/wp-admin/admin.php?page=currency-rates |
| Настройки (админка) | http://localhost:8080/wp/wp-admin/admin.php?page=currency-settings |
| Логин / пароль | `admin` / `admin` |

**http://localhost:8080/currency-rates/ — страница, которую стоит открыть первой.** На ней стоит
блок, описанный ниже: живой конвертер по сохранённым курсам и полная таблица курсов под ним.
`make bootstrap` публикует её, поэтому на чистом клоне она уже есть.

Админка находится по пути `/wp/`, а не `/wp-admin` — это раскладка Bedrock, и закладка от обычного
сайта на WordPress приведёт к 404.

Первый запуск занимает несколько минут, и почти всё это время Composer скачивает ядро WordPress и
зависимости. Последующие запуски занимают секунды.

## Ключ API

**Сайт запускается и работает без ключа.** Все пути, загружающие курсы, явно сообщают об ошибке, а
не сохраняют пустоту и не выдумывают курс, поэтому чекаут без ключа — это рабочий сайт с пустой
таблицей курсов.

Чтобы загружать реальные курсы, получите бесплатный ключ на
[freecurrencyapi.com](https://freecurrencyapi.com/) и укажите его в `.env`:

```bash
FREECURRENCYAPI_KEY=fca_live_...
```

Затем выполните `bin/wp currency rates update --force`.

`.env` не попадает в git и не должен туда попадать — в нём пароль от базы данных и восемь солей.
`.env.example` содержит структуру с пустыми секретами. Ключ передаётся в API HTTP-заголовком, а не
query-параметром, поэтому он не может утечь в логи доступа или в кэш прокси.

Бесплатный план допускает **5000 запросов в месяц**. Модуль делает один запрос в сутки и
отказывается от повторного запуска в течение 24 часов без `--force`, поэтому нагруженный сайт не
израсходует квоту.

## Как пользоваться модулем

### Сервис конвертации

Сигнатура — ровно та, которую требует техническое задание:

```php
$converter = new Drozd\Currency\Service\CurrencyConverter(
    new Drozd\Currency\Db\WpdbRateRepository()
);

$converter->convert( 123, 'USD', 'RUB' );   // 11439.876185174
```

Курсы хранятся относительно единственной базы USD, а любая другая пара выводится арифметически,
поэтому `EUR → RUB` работает без отдельной строки для `EUR`. Неизвестная валюта бросает
`UnknownCurrencyException`; пара, для которой нет сохранённого курса, — `RatesUnavailableException`.
Ни один из путей никогда не возвращает исходное значение, курс 1:1 или ноль.

### WP-CLI

```bash
bin/wp currency convert 123 USD RUB      # конвертировать сумму
bin/wp currency rates update             # загрузить курсы (пропустится, если свежие)
bin/wp currency rates update --force     # загрузить, игнорируя окно свежести
bin/wp currency rates list               # все сохранённые курсы
bin/wp currency currencies list          # предопределённый список валют
bin/wp currency doctor                   # проверить конфигурацию, схему, ключ, квоту
```

К обеим командам `list` применимы `--format=csv`, `--format=json` и `--format=count`.

### Админка

- **Currency Rates** — все сохранённые курсы, с сортировкой и с общим счётчиком, совпадающим с
  базой данных.
- **Settings** — состояние ключа API (только наличие и последние четыре символа, никогда само
  значение), время последней синхронизации и кнопка «Update now».

### Блок — `Currency Rates`

Фронтенд модуля и то, что показывает http://localhost:8080/currency-rates/. Вставляется из
инсертера блоков в разделе **Виджеты → Currency Rates** либо напрямую:

```
<!-- wp:currency-converter/rates /-->
```

Блок рисует конвертер — сумма, из какой валюты, в какую, результат — и таблицу сохранённых курсов
под ним. В боковой панели настраиваются базовая валюта, число строк и то, показывать ли конвертер,
таблицу и строку со временем обновления.

Два решения здесь сделаны намеренно:

- **Блок динамический.** В содержимое записи ничего не сохраняется, поэтому посетитель видит курсы,
  которые лежат в базе сегодня, а не те, что были при последнем открытии редактора.
- **Браузер не считает.** Конвертер обращается к
  `GET /wp-json/currency-converter/v1/convert`, а тот выполняет тот же путь через `bcmath`, что и
  CLI. В JavaScript один числовой тип, и это float; модуль существует именно потому, что float
  теряет деньги. Эндпоинт публичный, только на чтение, и никогда не обращается к
  freecurrencyapi.com — израсходовать квоту он не может.

### Шорткод

```
[currency_convert amount="123" from="USD" to="RUB"]
```

Выводит `$123.00 = ₽10,182.68` — обе стороны в символах и с числом знаков своей валюты, поэтому у
иены дробной части не будет. Разделители берутся из локали сайта (по умолчанию `en_US`), а число
знаков после запятой — из метаданных валюты, а не из константы. Если нужен конвертер, которым можно управлять, используйте блок выше.

## Повседневные команды

```bash
make help                     # список всех целей
make up / make down           # запустить / остановить контейнеры, сохранив данные
make reset                    # удалить базу данных, web/wp и vendor/, собрать заново
make build                    # пересобрать образ app (после изменения Dockerfile)
make test                     # PHPUnit внутри контейнера app
make lint / make lint-fix     # стандарты кодирования по нашему собственному коду
make logs S=cron              # смотреть логи одного сервиса
make db                       # консоль MariaDB
make screenshots              # снять скриншоты админки в docs/screenshots/

bin/wp <команда>              # WP-CLI в контейнере wpcli
bin/composer <команда>        # Composer от имени пользователя хоста
```

`make screenshots` — единственная команда здесь, которой нужно что-то за пределами Docker: Node на
хосте и `npm install` для Playwright. Больше ничему в этом файле, как и установке выше, это не нужно.

`make reset` удаляет `web/wp` и `vendor/` — и то и другое создаётся Composer. `web/app` остаётся на
месте, поэтому плагин, темы и загрузки не затрагиваются.

## Структура

```

```

## Сервисы

| Сервис | Образ | Роль |
|---|---|---|
| `db` | `mariadb:10.11` | база данных с healthcheck, которого ждут остальные |
| `app` | собирается из `Dockerfile` | PHP 8.3 + Apache, отдаёт `web/` |
| `composer` | `composer:2` | по требованию, за `bin/composer` |
| `wpcli` | `wordpress:cli-php8.3` | по требованию, за `bin/wp` |
| `cron` | `wordpress:cli-php8.3` | выполняет назначенные cron-события каждые 60 с |

WP-Cron отключён — `wp-cron.php` срабатывает только при загрузке страницы, поэтому на сайте, куда
никто не заходит, ежедневное обновление курсов не выполнялось бы никогда. Настоящий планировщик —
контейнер `cron`.

MariaDB вместо MySQL 8 — сознательно: в MySQL 8.0.19+ убрали ширину отображения целых чисел, поэтому
`bigint(20)` в определении схемы перестал совпадать с `bigint`, который возвращает `DESCRIBE`, и
`dbDelta()` начинает выдавать бессмысленный `ALTER` при каждой активации плагина.

## Три ловушки

Все три стоили здесь времени, и ни одной нет в документации вышестоящих проектов.

**1. `wp config get` не видит конфигурацию.** `Roots\WPConfig\Config::apply()` определяет константы
во время выполнения, а `wp config get` разбирает `wp-config.php` статически и ничего не находит.
Проверяйте через `bin/wp eval 'var_dump( WP_DEBUG );'`. Иначе «не задано» и «задано, но недоступно
этому инструменту» выглядят одинаково.

**2. Наборы PHP-расширений в контейнерах различаются.** У `app` и у `wpcli`/`cron` разные наборы —
`intl` есть в CLI-образе и отсутствует в `app`. Проверка, выполненная только через `bin/wp`, ничего
не говорит о том, что произойдёт при запросе из браузера; именно поэтому модуль использует
`number_format_i18n()`, а не `NumberFormatter`.

**3. Пути Bedrock отличаются от привычных.** Вход — `/wp/wp-login.php`, админка — `/wp/wp-admin`,
контент отдаётся из `/app`, а не из `/wp-content`.

## Устранение неполадок

**Порт 8080 занят** — задайте `HTTP_PORT` в `.env` (`WP_HOME` следует за ним), затем
`make down && make bootstrap`.

**Сайт недоступен после смены `HTTP_PORT`** — сохранённые в базе адреса всё ещё указывают на старый
порт. Помогает `make reset` либо обновление `home` и `siteurl` через `bin/wp option update`.

**`docker daemon is not running`** — bootstrap проверяет это первым делом и останавливается.
Запустите Docker Desktop.

**404 на всех страницах, кроме главной** — отсутствует `web/.htaccess` или выключен `AllowOverride`.
Файл под контролем версий, восстановите его.

**Таблица курсов пуста** — это ожидаемо без ключа API. Проверьте через `bin/wp currency doctor`.

**Начать с нуля** — `make reset` удаляет базу данных, `web/wp` и `vendor/`, затем выполняет
bootstrap заново.
